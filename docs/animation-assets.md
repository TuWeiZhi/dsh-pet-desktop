# 桌宠动画素材：制作、提示词与参考

本页记录桌面版便签动画的制作思路、曾提供给用户的豆包提示词、参考图片，以及本仓库实际使用的透明 WebM 处理参数。也介绍如何给现有桌宠添加普通随机动作。

桌宠角色及大量内置动画继承自 [PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet)，许可及来源见 [NOTICE](../NOTICE.md)。参考项目的[完整素材生成流程](https://github.com/PC2005-cloud/dsh-pet/blob/31aa345b11a18fc16d5fd35c42b8b9441071170e/MAKE-YOUR-OWN-PET.md)和[10 秒动作提示词](https://github.com/PC2005-cloud/dsh-pet/blob/31aa345b11a18fc16d5fd35c42b8b9441071170e/prompts/%E6%A1%8C%E9%9D%A2%E5%AE%A0%E7%89%A9%2010%20%E7%A7%92%E5%8A%A8%E4%BD%9C%E6%8F%90%E7%A4%BA%E8%AF%8D.md)介绍了绿幕生成、抠像和编码。该项目说明其素材由豆包生成。

本桌面版不包含上游的完整素材生成脚本。当前便签动画使用用户提供的豆包生成视频，经过本页记录的 FFmpeg 处理接入；睡觉三段则直接来自上游，不属于本次豆包生成素材。

## 便签动画：豆包提示词

每段先提供对应参考图，再把「通用要求」和相应动作段一起发送。图像生成结果存在随机性：先确认拿出动作的最后一帧，再用于生成其余四段，检查首尾姿势、画幅、地面线和手的位置。

### 通用要求

```text
请根据我上传的参考图片生成桌面宠物动画。

【角色】
保持参考图中蓝发 Q 版女仆桌宠的角色身份一致：
发型、发色、脸部、眼睛、服装、头饰、身体比例和画风都不要改变。
角色是二维动画形象，不是照片、亚克力立牌、玩偶或真人。

【画面】
横屏 16:9，镜头固定，不推拉、不旋转、不切换场景。
背景是均匀的纯绿色绿幕 #00FF00，没有桌面、键盘、房间、
支架、阴影、渐变、边框和其他物品。

角色始终位于画面中央，大小保持一致。
角色、手、便签、裙摆和脚部不能超出画面，也不能被画面边缘裁切。

【便签造型】
最终构图参考图片中的便签造型：
便签是位于人物下方的横向浅色矩形纸条，处于人物身体前方。
人物的头部和上半身从便签后方露出，脸始终不被便签遮挡。
画面右侧的手自然搭在便签上沿，画面左侧的手自然抬起。

便签不要出现在头顶，不要变成头顶举牌，
也不要让角色双手向上托着便签。

便签表面平整、不透明、浅色，大小和位置保持稳定，
中间留出足够书写五行文字的空白区域。
便签表面和画面中不要生成任何文字、数字、按钮、页码、水印或图标。

【动作】
动作自然平稳，保持手部结构正确。
不要出现多余的手、手指、道具、角色或身体部位。
```

### 1. 拿出便签：图片 A + 便签构图参考

```text
生成一段约 5 秒的动画。

第一帧：角色与图片 A 一致，正面站立，双手自然放下，画面中没有便签。
0～1 秒：角色保持站立，轻轻眨眼，然后准备从身后拿东西。
1～3 秒：角色自然地将手伸向身后，从身后抽出一张横向浅色便签，
缓慢移动到身体下方的前面。便签不要经过或遮挡角色的脸。
3～5 秒：便签稳定停在人物下方，角色的头部和上半身从便签后方露出。
画面右侧的手自然搭在便签上沿，画面左侧的手自然抬起。

最后保持便签位于人物下方、角色面向前方、姿势稳定。
不要收回便签，不要把便签举到头顶。便签表面保持完全空白。
```

### 2. 便签待机：图片 A + 拿出动画的最后一帧

```text
请以提供的便签终态图作为第一帧，生成一段约 5 秒的便签待机动画。
角色保持头部和上半身位于便签上方的姿势，一只手搭在便签上沿，另一只手自然抬起。
角色可以轻轻眨眼、自然呼吸，头发末梢有非常轻微的摆动。
便签的位置、大小、角度和形状始终不变，上沿和搭在上沿的手尽量保持稳定。
便签表面始终平整、空白，不出现文字和数字。
最后一帧尽量与第一帧一致，以便循环播放时自然衔接。
```

### 3. 上一页：图片 A + 便签终态图

```text
请以便签终态图作为第一帧，生成一段约 3 秒的便签翻页动画。
角色与便签保持原来的位置，便签固定在人物下方。
0～1 秒：角色的左侧手自然移动到便签的左上角。
1～2 秒：角色在便签左上角附近轻轻抽动一张空白纸条，表现翻到上一页。
纸张不要遮挡角色的脸。
2～3 秒：翻页结束，手回到参考图姿势。
角色和便签恢复到与第一帧一致的位置和大小。
整个过程中便签外框保持稳定，不上下移动、不旋转、不变形；
便签表面始终为空白，不要生成文字、页码或按钮。
```

### 4. 下一页：图片 A + 便签终态图

```text
请以便签终态图作为第一帧，生成一段约 3 秒的便签翻页动画。
角色与便签保持原来的位置，便签固定在人物下方。
0～1 秒：角色的右侧手从便签上沿自然移动到便签的右上角。
1～2 秒：角色在便签右上角附近轻轻抽动一张空白纸条，表现翻到下一页。
纸张不要遮挡角色的脸。
2～3 秒：翻页结束，手回到参考图姿势。
角色和便签恢复到与第一帧一致的位置和大小。
整个过程中便签外框保持稳定，不上下移动、不旋转、不变形；
便签表面始终为空白，不要生成文字、页码或按钮。
```

### 5. 收起便签：图片 A + 便签终态图

```text
请以便签终态图作为第一帧，以图片 A 的正面站立姿势作为最终姿势，
生成一段约 5 秒的动画。
第一帧：角色保持便签造型，便签位于人物下方。
0～2 秒：角色自然收回抬起的手，准备收起便签。
2～4 秒：角色将便签向身体后方收起，便签不要经过或遮挡角色的脸，
便签逐渐从画面中消失。
4～5 秒：角色双手自然放下，恢复到图片 A 的正面站立姿势。
最后一帧只有正面站立的角色，没有便签和其他道具；
角色的位置、大小和姿势尽量与图片 A 一致。
```

## 本次视频的处理方式

实际源视频均为 1280×720、24 fps，时长约 4～5 秒；绿幕偏浅且含阴影，部分画面含角落水印或便签内箭头。提示词中的纯绿幕和空白便签不是生成结果的保证。

本次处理使用 FFmpeg `N-121256-g0fdb5829e3-20250929`：先保留原画幅中 `x=290, y=40, 宽=700, 高=660` 的区域，再按像素的绿色分量计算透明度，补回原画布，缩到 640×360，最后以 VP9 Alpha 编码。裁剪区域同时排除了画面角落的水印；便签内箭头仍在视频中，由应用内便签面板覆盖。源视频摆位、背景颜色或道具范围变化时，**不能直接假定这组裁剪与抠像参数仍适用**，应逐段检查边缘、阴影、手和纸张是否保留完整。

以下 PowerShell 命令以「拿出」为例，先输出到临时的 `素材预览` 文件夹，不覆盖项目成品；其余源文件按上表逐一替换。源视频路径可自行调整。

```powershell
New-Item -ItemType Directory -Force -Path '素材预览' | Out-Null
$filter = "crop=700:660:290:40,format=rgba,geq=r='r(X,Y)':g='g(X,Y)':b='b(X,Y)':a='255*(1-clip((min(g(X,Y)-r(X,Y),g(X,Y)-b(X,Y))-3)/12,0,1))',pad=1280:720:290:40:color=black@0,scale=640:360,format=yuva420p"
ffmpeg -hide_banner -i '蓝发Q版女仆桌宠动画制作拿出标签.mp4' `
  -vf $filter -c:v libvpx-vp9 -crf 32 -b:v 0 -row-mt 1 -an `
  '素材预览/便签-拿出.webm'
```

核验透明通道时，FFmpeg 读取 VP9 时可显式指定 `-c:v libvpx-vp9`，并将视频放到不同颜色背景上检查；部分播放器对透明 WebM 的显示可能不同。检查通过后再替换对应 `assets/webm/便签-*.webm`，并验证拿出→待机→翻页→待机→收起的衔接。对于复杂道具、绿色服装或自动抠像残边，上游文档还提供手工抠像和导入透明 MOV 的路线。

生成视频只负责人物和便签的视觉动作；五行输入、左右翻页点击区、页码和保存由 `runtime/electron-helper/note.js`、`note-pages.js`、`note.css` 实现。桌面端通过 `runtime/electron-helper/sprite.js` 直接加载五个固定名称的包内视频，不通过普通随机动作配置加载。更换便签素材后应运行：

```powershell
node tools/verify-desktop.mjs
node --test src/host/note-pages.test.cjs
.\node_modules\.bin\electron.cmd tools/note-smoke.cjs --pages
```

## 给现有桌宠添加普通动作

普通动作建议约 10 秒、16:9、固定镜头与绿幕；首尾回到一致的标准站姿，让动作间切换更自然。生成绿幕视频、抠像并输出透明 WebM 后，主配置宠物的用户素材放入 `%APPDATA%\dsh-pet\main-animation\webm\`，文件名与配置中动画名一致，不带扩展名。用户目录的同名文件优先于包内素材。

修改 `%APPDATA%\dsh-pet\main-config.jsonc` 前先备份；在 `animations.categories` 中的现有分类 `actions` 数组追加动作名。`animations` 按整段覆盖：用户配置若没有该段，需要从 [assets/config.jsonc](../assets/config.jsonc) 复制完整的 `animations` 段再修改，不能只写一个分类。保存后右键「重载配置」，从「动作」菜单先手动点播检查，再观察自动播放。

睡觉不是普通动作：当前桌面版使用包内 `睡觉-开始`、`睡觉-循环`、`睡觉-起来` 三段及专门的手动状态机。它不参与普通动作池的随机选择，也没有梦话功能。
