# 桌宠动画素材制作指南

本文介绍制作和接入桌宠动画的通用方法：**准备角色参考 → 编写动作提示词 → 生成绿幕视频 → 抠像和统一规格 → 接入桌面版 → 检查播放**。可以用豆包等支持参考图的视频生成工具，也可以使用手工制作的视频。

桌宠角色及大量内置动画继承自 [PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet)，来源与许可见 [NOTICE](../NOTICE.md)。本文参考其[素材制作流程](https://github.com/PC2005-cloud/dsh-pet/blob/main/MAKE-YOUR-OWN-PET.md)和[动作提示词](https://github.com/PC2005-cloud/dsh-pet/blob/main/prompts/%E6%A1%8C%E9%9D%A2%E5%AE%A0%E7%89%A9%2010%20%E7%A7%92%E5%8A%A8%E4%BD%9C%E6%8F%90%E7%A4%BA%E8%AF%8D.md)。参考项目说明其素材使用豆包生成。

## 1. 准备角色参考

选一张角色清楚、正面、全身完整的图片，确定发型、服饰、比例和风格。制作同一套宠物时，尽量使用同一张标准站姿参考图，减少角色形象和位置漂移。

为现有内置宠物增加动作时，也可以从仓库中的待机视频提取一帧。下面的命令在项目根目录执行，输出到当前目录，需要安装 FFmpeg；`libvpx-vp9` 用于读取透明 WebM：

```powershell
ffmpeg -ss 0.3 -c:v libvpx-vp9 -i 'assets/webm/待机呼吸休闲.webm' `
  -frames:v 1 '角色参考.png'
```

如要制作其他角色，改用自己的角色参考图。生成工具可能不完全遵守参考图；选片时要逐段检查角色一致性。

## 2. 确定动画类型和衔接

普通随机动作通常是一段约 10 秒的视频：从标准站姿开始，完成动作，再回到相近的标准站姿。这样与其他动作切换时更自然。动作幅度、道具与特效应始终留在画幅内。

需要维持某种状态的动作，可以拆成多段：

| 片段 | 作用 | 画面衔接 |
| --- | --- | --- |
| 开始 | 从站姿过渡到目标状态 | 起点对齐标准站姿，终点对齐循环起点 |
| 循环 | 持续维持目标状态 | 首尾尽量一致，便于连续播放 |
| 结束 | 从目标状态恢复 | 起点对齐循环状态，终点回到标准站姿 |

拍摄或生成时，保持同一角色大小、水平位置和脚底基线，并给四周保留空间；带道具的普通动作应在结束前清理道具。跨段先检查末帧与下一段首帧，避免跳变。

**多段视频需要应用代码或已有状态机负责切换**，不会因为放入素材目录就自动形成循环。普通动作也不要仅靠视频中的画面表达需要真实点击、输入或保存的功能；交互行为要由程序实现。

## 3. 通用视频生成提示词

把角色参考图上传至生成工具，替换以下方括号中的内容。先写清动作，再按时间段描述开始、过程和结束：

```text
请以我上传的图片作为角色参考，生成一段约 10 秒的二维桌面宠物动画。

【角色与风格】
保持参考图中角色的发型、发色、脸部、服装、配饰、比例和画风一致。
角色为完整的二维动画形象，不要变成真人、玩偶或其他角色。

【画面】
横屏 16:9，镜头固定，不推拉、不旋转、不切换场景。
背景使用均匀的纯绿色绿幕 #00FF00，没有背景图案、渐变或场景物品。
人物位于画面中央，大小和脚底基线与参考图保持一致。
动作、身体、道具和特效全程留在画面内，四周保留空间，不触碰画面边缘。

【动作】
动作名称：[填写动作名称]
动作内容：[描述人物、表情、道具以及动作的方向和幅度]
0～3 秒：[从标准站姿如何开始]
3～7 秒：[动作的主要过程]
7～10 秒：[如何结束并恢复站姿]

第一帧为干净的标准站姿；最后一帧尽量恢复到同一站姿和位置。
动作自然平稳，不出现多余的身体部位、文字、边框或无关人物。
```

如果制作循环或多段状态，分别写明每段的起始姿势、结束姿势和时长；循环段不要要求回到站姿。可将上一段满意的末帧作为下一段的姿势参考，但仍需人工核对衔接。提示词只是目标，不保证生成工具严格遵循。

## 4. 绿幕视频转成透明动画

### 路线 A：参考项目的素材链

[参考项目完整流程](https://github.com/PC2005-cloud/dsh-pet/blob/main/MAKE-YOUR-OWN-PET.md)提供了自动抠绿幕、手工抠像导入、角色归一化和播放版编码。该素材链在**上游仓库**，不在本桌面版仓库中。

使用时先获取上游仓库并阅读其脚本：上游当前脚本需要 Python 3、`numpy`、`scipy` 和 FFmpeg；脚本将 FFmpeg 与 FFprobe 写死在上游仓库 `.tools/ffmpeg-9.0.1-essentials_build/bin/` 下，普通系统 PATH 不会自动替代这个路径。上游自动抠像脚本按 1280×720、24 fps 处理输入，生成的播放版为 640×360 VP9 Alpha WebM。具体路径和依赖以获取的上游脚本为准。

源视频进入 `step01/` 后，可以在上游仓库根目录依次运行：

```powershell
py scripts/chroma_step02.py       # 绿幕转透明，输出 step02/
py scripts/normalize_step03.py    # 统一画布、角色大小和脚底线，输出 step03/
py scripts/encode_thumbs.py       # 转为播放版，输出 step04/
```

这三个脚本会处理各自输入目录下的文件；使用前先检查目录内容。上游还提供 `watermark_step01.py` 和 `pr_import_step02.py`：前者依赖特定遮罩，后者用于导入手工抠好的带 Alpha MOV，使用条件见上游文档，不能假定所有视频都适用。

### 路线 B：用 FFmpeg 快速处理单段绿幕

对于背景接近纯绿、构图已符合目标规格的 16:9 视频，可以先用下面的命令尝试。需要支持 `libvpx-vp9` 的 FFmpeg；输出是 640×360、带 Alpha 的 VP9 WebM，无音轨。此方法仅缩放画幅，**不自动统一不同视频的人物大小与脚底位置**。

```powershell
ffmpeg -i '动作源视频.mp4' `
  -vf 'format=rgba,colorkey=0x00FF00:0.18:0.06,scale=640:360:flags=lanczos,format=yuva420p' `
  -c:v libvpx-vp9 -crf 32 -b:v 0 -an '动作名称.webm'
```

`colorkey` 的颜色、相似度和边缘过渡需要根据实际视频调整；绿色服装、道具、阴影、绿色反光或非纯色背景可能被误抠或留下边缘。源视频不是 16:9 时应先调整构图，再按目标尺寸转换，避免拉伸。FFmpeg 参数含义可参考其 [colorkey 文档](https://ffmpeg.org/ffmpeg-filters.html#colorkey)。

### 检查素材

- 在浅色和深色背景上检查透明边缘，尤其是头发、手、道具、阴影和特效。支持情况因播放器而异；可用实际桌面程序核对。
- 比较不同动作的角色大小、画面中心和脚底基线，并检查首尾或跨段姿势是否匹配。
- 确认视频中没有意外文字、遮挡或裁切。`ffprobe` 可以检查分辨率和时长，但不能单凭文件扩展名或视频流信息判断透明效果；用 FFmpeg 读取 VP9 Alpha 时可显式指定 `-c:v libvpx-vp9`。

## 5. 接入桌面版普通动作

主配置宠物可将自定义透明 WebM 放在：

```text
%APPDATA%\dsh-pet\main-animation\webm\动作名称.webm
```

用户目录中的同名素材优先于包内素材；使用新名称可避免覆盖现有动作。自定义宠物种类使用其自己的素材目录，查找规则见 [assets/config.jsonc](../assets/config.jsonc)。

修改 `%APPDATA%\dsh-pet\main-config.jsonc` 前先备份。给 `animations.categories` 中某个分类的 `actions` 数组追加动画名，名称与文件名一致，**不写 `.webm`**。示例只展示一个数组的局部，原有项目需保留：

```jsonc
"actions": [
  "已有动作",
  "动作名称"
]
```

`animations` 是整段覆盖：用户配置已有该段时，直接修改现有完整段；没有时，从 [assets/config.jsonc](../assets/config.jsonc) 复制完整的 `animations` 段，再追加新动作，不要只写一个分类。保存后右键宠物选择「重载配置」，从「动作」菜单点播新动画，确认无黑底、无裁切、位置正确；再检查自动动作间隔。

如果要随软件安装包一起发布普通动画，需将文件和配置变更加入项目并重新构建。睡觉等状态动作有专门的播放逻辑，不能简单加入普通动作分类来获得相同的状态行为。

## 6. 当前大便签视频（2026-11-06）

便签使用根目录中新提供的五段 `桌宠…` MP4，经 `tools/prepare-note-videos.py` 生成到 `assets/note-video/`。根目录中的旧版 `蓝发Q版…` 视频及图片帧试作不参与这条制作链路。

| 动作 | 根目录源文件 | 帧数 / 时长 |
| --- | --- | --- |
| 拿出 | `桌宠“拿出便签”连续动画生成需求.mp4` | 121 / 5.04 秒 |
| 待机 | `桌宠持签待机循环动画生成需求.mp4` | 121 / 5.04 秒 |
| 上一页 | `桌宠“上一页”动作生成.mp4` | 97 / 4.04 秒 |
| 下一页 | `桌宠“下一页”动作生成.mp4` | 97 / 4.04 秒 |
| 收起 | `桌宠“收起便签”连续动画生成需求.mp4` | 121 / 5.04 秒 |

处理保留每一帧和 24 fps，去除绿幕、抑制边缘溢绿、去掉音轨，并对每段整幅画面作固定尺寸/位置校准。待机片的原始纸张略高，整幅纵向校准量约 5%；随后整幅缩至 90%，对齐普通待机的人物高度与脚底位置。纸面按每段固定的 RGB 偏移统一为暖纸色，保留原纹理、阴影与动作；没有重画、替换纸张或合成角色动作。输出保留 4:3 透明画布，编码为 640×480 VP9 Alpha WebM；源文件、SHA-256 与校色值记录在 `assets/note-video/sources.json`。

复现需要 Python 的 `numpy`、`opencv-python-headless` 和支持 `libvpx-vp9` 的 FFmpeg：

```powershell
python tools/prepare-note-videos.py --ffmpeg C:/ffmpeg/bin/ffmpeg.exe
```

运行时 `note-film.js` 完整绘制视频帧，`note-media-data.js` 保存纸面坐标和播放速度。文字在拿出视频的 3.5 秒处、纸面稳定后显示（2 倍速播放约 1.75 秒），翻页时隐藏。拿出为 2 倍速，约 2.52 秒；上一页、下一页及收起为 4 倍速，翻页约 1.01 秒，收起约 1.26 秒；待机保持原速。连续点击即时更新页码和内容，共用正在播放的一次动画，不逐页排队；反向点击同样更新到最新目标，关闭后保留最新页，旧动画回调失效。人物、纸张和文字始终按设置尺寸等比例缩放，直接在手持纸张上编辑，不展开独立便签。每页固定五行：可写区域占纸张高度的 90%，每行占纸张高度的 18%，字号为纸张高度的 13.8%；上下各留 5%、左右各留 4%。使用纸面作为 CSS 尺寸查询容器，让字号、行高和留白一起缩放；分页逻辑明确使用五行，避免小数像素取整导致少一行。翻页按钮和页码位于纸张下沿，纳入悬停及原生鼠标输入区域；末页写满后可以新增一页，重新分页保留原文和当前文本位置。跨视频加载期间保留上一帧，首帧解码后用 180 毫秒混合过渡；待机循环接缝同样处理，减少动态效果设置会禁用新增的混合过渡。

从日常动画进入便签时，单独使用 350 毫秒过渡：按屏幕显示顺序截取 A/B 两层视频，保留当前 CSS 透明度、变换和变换原点，立即显示这张合成画面并隐藏普通视频；便签首帧解码前保持画面不变，随后再开始渐变。收起末尾同样使用 350 毫秒缓入缓出，过渡到完整的日常合成画面，避免切回时跳变；这段过渡包含在收起动画时长内，不额外等待。便签内部片段仍使用上述 180 毫秒过渡；减少动态效果设置会禁用渐变，但仍保留加载期间的画面。

旧 `assets/note-layers/` 和 `tools/retouch-note.py` 仅保留作历史材料，不再被便签调用，前者已排除出安装包。可运行 `node --test src/host/note-film.test.cjs src/host/note-animation.test.cjs src/host/note-pages.test.cjs`、`electron tools/note-smoke.cjs --handoff`、`electron tools/note-smoke.cjs --pages`、`electron tools/note-smoke.cjs --appearance` 和 `electron tools/note-smoke.cjs --film` 检查画面交接、交互、纸色、缩放与实际渲染。单独生成的片段仍存在细微画风、纹理差异，应以完整播放预览判断接缝，不能仅以测试通过判断美术效果。

`--film` 是逐帧导出预览：定位到每帧中点，等待 `seeked` 确认解码完成，再等待页面绘制并保存。不能仅等待 `requestVideoFrameCallback`，它可能先返回旧帧，此时视频仍在跳转，画布会保留上一帧。导出会检查相邻源帧截图是否重复，避免旧画面造成卡顿。当前预览应按输出提示以 96 fps 编码，保留 4 倍速动作的每一帧；2 倍速拿出每帧显示两次，原速待机每帧显示四次，保持各自的节奏。
